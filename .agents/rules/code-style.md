# Fodinae Code Style & Formatting Guidelines

Это эталонный стандарт написания кода для проекта **Fodinae**, выведенный из конфигураций линтеров (`.editorconfig`, `.stylecop.json`, `Directory.Build.props`) и статического анализатора Roslyn.

---

## 1. Структура и скобки (Braces & Formatting)

* **Табуляция и переносы**: 4 пробела (`indent_size = 4`), окончания строк `LF`, кодировка `UTF-8`.
* **Перенос скобок (Allman Style)**: Каждая открывающая фигурная скобка `{` пишется с **новой строки** (`csharp_new_line_before_open_brace = all`).
* **Ключевые слова ветвления**: `else`, `catch`, `finally` пишутся только с новой строки.
* **Обязательность скобок**: Всегда используйте фигурные скобки `{}` даже для однострочных `if`, `for`, `foreach` блоков (`csharp_prefer_braces = true`, `SA1503`).
* **Пустые строки вокруг скобок**:
  * После закрывающей фигурной скобки `}` обязательна пустая строка (`SA1513`).
  * Не допускается пустая строка непосредственно перед закрывающей скобкой `}` (`SA1508`).
* **Запятая в инициализаторах (Trailing Comma)**: Многострочные списки, массивы и инициализаторы объектов обязаны завершаться запятой (`SA1413`).
* **Комментарии**: Одиночным строчным комментариям `//` должна предшествовать пустая строка (`SA1515`).

## 2. Современный C# 12 и Синтаксис

* **Пространства имён (Namespaces)**:
  * Для обычных C#-типов используйте **file-scoped namespace**: `namespace Fodinae.Domain;`.
  * **Исключение Unity**: `MonoBehaviour` и `ScriptableObject` ОБЯЗАНЫ использовать блочный namespace `namespace Fodinae.Domain { ... }`, чтобы исключить сброс `MonoScript` в Unity.
* **Nullable Reference Types**: Размечайте `string?`, `null!`. Проект компилируется без ворнингов `CS86xx`.
* **Record Structs**: Для легковесных структур используйте `readonly record struct` и первичные конструкторы (Primary Constructors).
* **Collection Expressions**: Для инициализации массивов и списков используйте `[]` вместо `new List<T>()` или `new T[]`.
* **Expression-Bodied Members**: Применяйте стрелочный синтаксис `=>` для однострочных методов, свойств и геттеров/сеттеров.
* **Правила `var`**:
  * Используйте `var`, если тип явно виден из правой части выражения (`var list = new List<string>();`).
  * Для примитивных типов (`int`, `float`, `string`, `bool`) указывайте тип явно.

## 3. Правила именования (Naming Conventions)

* **Интерфейсы**: Начинаются с заглавной `I` в `PascalCase` (`IMapDataProvider`, `IAudioSystem`).
* **Приватные / protected поля**: Начинаются с префикса `_` в `camelCase` (`_mapManager`, `_terrainRenderer`).
* **Публичные / internal члены**: Метод, свойство, событие или поле в `PascalCase` (`Execute()`, `PlayerPosition`).
* **Локальные переменные и параметры**: В `camelCase` (`chunkPos`, `expectedSize`).
* **Константы**: Разрешены в `PascalCase` или `UPPER_SNAKE_CASE`.

---

## 4. Архитектура и производительность Unity

* **VContainer DI**: Никаких новых статических `.Instance` синглтонов! Используйте `[Inject]` или конструкторы.
* **Zero-Allocation на кадрах**:
  * Не вызывайте `GetComponent` или `Find` внутри `Update()` / `FixedUpdate()`.
  * Не выделяйте массивы в куче (например, `new Vector3[4]`) в методах отрисовки кадра.
* **Обработка ошибок**: Запрещено пустое глотание ошибок `catch {}`. Всегда обработайте или залогируйте исключение (`CA1031`, `S108`).
* **Gizmos**: Для отладки используйте `FodinaeGizmos` и атрибут `[Conditional("UNITY_EDITOR")]`.
