# Предложение: семантика вместо пикселей в GUI-пакетах

**Кому:** владельцу `MinesReborn/MinesServerNetworking`
**От:** клиент Fodinae (Unity 6000.5, UI Toolkit)
**Статус:** предложение. Фаза 1 не требует изменений в протоколе вообще.

---

## Коротко

Сервер сейчас присылает окну цвета в ARGB и отступы в пикселях. Клиент из-за
этого не может применить к серверным окнам ни тему, ни размер экрана, ни
настройки доступности игрока, ни подгонку под длинные переводы.

Просьба одна: дать серверу способ сказать **что** он показывает, а не **как**
это выглядит. Способ уже есть в протоколе — поле `AttachedProperties`. Фаза 1
не требует ни новых полей, ни версии, ни синхронного релиза.

---

## Что происходит сейчас

`GUIStylePacket` (`Server/Packets/GUI/Components/GUIStylePacket.cs`):

```csharp
public Color Background { get; init; }   // System.Drawing.Color -> ARGB
public Color Border     { get; init; }
public byte  BorderWidth { get; init; }
public Margins Margin   { get; init; }   // byte Top, Left, Bottom, Right
public Margins Padding  { get; init; }
```

`OpenWindowPacket` дополнительно несёт `ushort Width, ushort Height`.

Клиент раскладывал это напрямую в инлайн-стили элемента. В UI Toolkit инлайн
выигрывает у **любого** правила таблицы стилей, поэтому серверные окна
оказывались вне дизайн-системы целиком.

### Четыре следствия, каждое проверяемое

1. **Тема не действует.** У клиента есть слой семантических токенов
   (`--surface-panel`, `--accent-gold`, `--border-subtle` — 148 штук,
   печатаются генератором из макета). Инлайн их перекрывает, так что сменить
   палитру или добавить светлую тему для серверных окон нельзя.

2. **Размер экрана не действует.** У клиента три тира (`tier--compact` <900,
   стандартный, `tier--wide` >=1600), в которых меняются кегли и крупные
   отступы. Пиксель с сервера одинаков на телефоне и на 4K-мониторе.

3. **Локализация ломается предсказуемо.** По замерам на собственных словарях
   игры: строка длиной до 10 символов при переводе растёт в среднем в 1.67
   раза, в худшем случае — в 3.1. Окно, которому сервер назначил ширину в
   пикселях, обрежет немецкий или турецкий текст, и починить это на клиенте
   нельзя — ширина пришла как приказ.

4. **Доступность не действует.** У клиента есть переключатель «меньше
   движения» и он гасит анимации через токены. Инлайн мимо этого механизма.

### Отдельно: текст ходит готовым, а не ключом

`ModalWindowPacket(string Title, string Description, string ButtonText, string IconURI)`
— это отображаемый текст, а не ключ словаря. Значит:

- перевести его на клиенте невозможно: языка игрока сервер не знает;
- словарь локализации клиента (853 ключа, 4 языка) на серверные окна не
  распространяется;
- при поддержке многих языков сервер должен будет хранить все переводы и
  знать язык каждого игрока — то есть решать задачу, которую клиент уже решил.

Просьба: рядом с текстом (или вместо него) передавать **ключ** и аргументы.

## Что предлагается

### Фаза 1 — без единой правки протокола

В `IGUIComponentPacket` уже есть:

```csharp
public StringPairPacket[] AttachedProperties { get; init; }
```

Клиент уже читает оттуда `Canvas.X` и `Canvas.Y`. Предлагается ещё три ключа
по соглашению — новых полей не нужно, версия протокола не меняется, старые
клиенты просто игнорируют незнакомые ключи:

| ключ | значение | пример |
|---|---|---|
| `ui.word` | имя из словаря вида | `modal-card` |
| `ui.variant` | вариант этого имени | `md` |
| `ui.text` | ключ локализации вместо готового текста | `trader.offer_title` |

Пример: вместо «фон #0b141e, рамка #56ddd4 45%, паддинг 16» сервер говорит
`ui.word=modal-card`, `ui.variant=md`. Клиент рисует это своими токенами,
своим тиром и на своём языке.

`GUIStylePacket` остаётся и продолжает работать: он становится **запасным
путём** для случаев, которые словарь не покрывает.

### Фаза 2 — когда фаза 1 приживётся

Перевести те же три ключа в типизированные поля (`Word`, `Variant`, `TextKey`)
и добавить `VocabularyVersion` в `OpenWindowPacket`. Это экономия трафика и
проверка на этапе компиляции, но выигрыш по существу даёт уже фаза 1.

## Словарь

Словарь не сочинён под протокол — он **извлечён из дизайн-системы клиента**
инструментом `visual/main-menu-mirror/tools/emit-vocabulary.py`. Отсюда
свойство, которое стоит отметить: не может существовать слова, которое клиент
не умеет нарисовать.

- файл: `visual/main-menu-mirror/protocol/ui-vocabulary.json`
- состав: **32 семейства с вариантами**, **258 одиночных слов**
- версия: хеш от состава, меняется при добавлении или удалении слова

Примеры семейств:

```
modal-card          sm | md | lg | xl | gold
btn-gold-action     sm | md
btn-outline-action  cyan | danger
progress-fill       ok | danger | full
sci-fi-badge-mono   gold | fit
```

Служебное в словарь не входит: зазоры, стопки, скрытие. Сервер называет роль;
отступ, цвет и порядок слоёв — следствие роли, а не часть пакета.

## Пример пакета

Полный файл: `visual/main-menu-mirror/protocol/example-packet.json`.

```json
{
  "op": "open-window",
  "id": "trader-offer-8841",
  "window": {
    "word": "modal-card",
    "variant": "md",
    "title": { "key": "trader.offer_title", "args": ["Красноскал"] }
  },
  "body": [
    { "word": "settings-row",
      "label": { "key": "trader.lot_name", "args": ["T-4"] },
      "value": { "word": "sci-fi-badge-mono", "variant": "gold", "text": "×12" } },
    { "word": "progress-track", "children": [
      { "word": "progress-fill", "variant": "ok", "fill": 0.71 } ] }
  ],
  "actions": [
    { "word": "btn-outline-action", "variant": "danger",
      "label": { "key": "trader.decline" }, "send": "trader.decline" },
    { "word": "btn-gold-action",
      "label": { "key": "trader.accept" }, "send": "trader.accept" }
  ]
}
```

Ни одного пикселя, ни одного цвета, ни одной строки отображаемого текста.
Проверено программно: все восемь слов есть в словаре, варианты допустимы.

## Правила деградации

Их надо утвердить, потому что от них зависит, можно ли катить сервер впереди
клиента.

| случай | поведение клиента |
|---|---|
| неизвестный **вариант** | рисуется базовое семейство без варианта |
| неизвестное **семейство** | узел пропускается, запись в лог |
| слова нет вовсе, есть `GUIStylePacket` | работает нынешний путь |
| ключ локализации не найден | показывается сам ключ, запись в лог |

Смысл: сервер новее клиента не должен ронять экран. Клиент называет версию
словаря в хендшейке, сервер не употребляет слов новее названной.

## Что клиент уже сделал со своей стороны

Не дожидаясь ответа — потому что часть проблемы решается и без протокола.

1. **Токены игры печатаются из макета.** `ThemeTokens.uss` больше не пишется
   руками: генератор `visual/main-menu-mirror/tools/emit-uss-tokens.py`.
   До этого связь держалась на просьбе в шапке файла и уже разъехалась —
   **16 токенов** имели разные значения в макете и в игре, худший
   (`--border-subtle`) отличался втрое и стоял почти на каждой поверхности.
   Расхождение теперь ловит CI.

2. **`StyleApplicator` перестал класть пиксели.** ARGB с сервера
   примагничивается к ближайшему токену палитры, и элемент получает **класс**
   вместо инлайна — класс подчиняется теме и тиру. Не попавшее в порог
   применяется по-старому и увеличивает счётчик промахов: «сервер попросил
   цвет, которого нет в палитре» видно, а не проглатывается.

   **Это компромисс, а не решение.** Клиент угадывает намерение по цвету.
   Угадывание не нужно, если сервер называет намерение сам, — ради этого и
   написан документ.
