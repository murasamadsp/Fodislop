Terrain texture upload telemetry

This capability belongs to TerrainCellBuffers, which owns the cell buffer (one ushort per cell, both layers, two cells per uint word, in a ring one cell wider than the window on each side) and the 256-row type table. A caller may read its UploadTelemetry capability; no mandatory member was added to the general frame telemetry contract.

Payload bytes are estimates of the texture data addressed by Unity API calls. They are not GPU bandwidth, bus traffic, compression-aware transfer size, or measured device work. The existing measured CPU upload durations remain available; only aggregate upload counts and bytes stay unknown because mesh and atlas upload producers are not covered.

Ownership and lifecycle — TL-OWN, TL-LIFE

TerrainCellBuffers owns one TerrainTextureUploadCounters instance for its lifetime. Each successful texture allocation starts a monotonically numbered generation after any old resources have been destroyed. The generation counter survives resize/reallocation; the four operation totals remain cumulative and checked for overflow. Starting a generation clears only the source-frame stamp and generation-local delta baseline; cumulative totals are not reset.

FrameTelemetry.ResetFrameTimers runs at the start of Terrain LateUpdate. Its upload snapshot is labelled with Time.frameCount - 1, because it observes cumulative calls completed before the current frame's terrain upload. The frame benchmark samples the live source when its coroutine observes the previous frame and records that observation frame separately. A frame delta is valid only when both snapshots are available, belong to the same texture generation, have adjacent observation-frame IDs, and cumulative values have not regressed. The delta may validly be zero on a stable frame. An initial sample, resize/generation change, disposal, missing reset/frame gap, stale endpoint, or regression yields an invalid delta; consumers must not infer zero. The source-frame stamp remains the most recent counted operation in the current generation and is never used as the observation endpoint.

The frame benchmark keeps the cell-data Apply and CopyTexture counts/bytes separate from legacy upload totals; those uncovered aggregate count/byte fields remain JSON null. Existing measured terrainGpuUploadTimeMs and terrainAtlasUploadTimeMs durations remain numeric and unchanged.

Performance scope — TL-PERF

Each recorded SetData adds the element count, the 16- or 32-byte stride, one Time.frameCount read, checked integer arithmetic, and counter writes. Cell-data uploads no longer issue CopyTexture calls; the CopyTexture totals stay zero for this owner. ResetFrameTimers adds one value snapshot and constant-size delta validation/subtraction work: O(1). There is one small counter object per buffer owner and no per-frame counter allocation. No-upload stable frames can report a valid zero delta between adjacent valid endpoints. These counters do not establish runtime cost or a performance improvement.

Verification — TL-VERIFY

The standalone tests link the production counter source directly. They check capability availability, generation changes, cumulative lifetime, source-frame behavior, allocated-dimension Apply estimates, rectangle CopyTexture estimates, and invalid dimensions. Unity production-path upload behavior was not run; these tests verify the accounting contract, not Unity or GPU behavior.

The standalone capture analyzer also checks these optional metrics for OPT-1 S0/S1/S4 samples when adjacent available cumulative endpoints exist in the same texture generation. It derives the delta from observation frame IDs, validates the duplicated observation and exported delta fields, and treats the last-upload source frame as a separate stamp. Positive Apply or CopyTexture deltas fail the stable-frame invariant independently of aggregate upload counters or GPU timing. Missing legacy fields are outside this conditional check and are not interpreted as zero; generation changes, unavailable endpoints, and observation gaps leave the check incomplete.

2026-09-29: endpoint observation IDs must also match the enclosing frame or baseline, not merely each other. Shifted adjacent samples and partial/unavailable endpoints cannot prove stable work. Contradictory call/byte deltas fail input validation; missing GPU/aggregate metrics cannot hide an independently established cell-data violation. The standalone suite passes 155 tests, including the lighting decision fixtures; this is not a Unity production capture.

The separate LightingFrameDumper uses Unity-serializable primitive fields: available and frameDeltaValid govern their validity. Numeric defaults when either flag is false are not measured zero. The strict benchmark JSON continues to use nullable metrics and must not be confused with this diagnostic dump format.
